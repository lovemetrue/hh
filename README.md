# hh-bot

Бот для откликов на hh.ru. Собирает вакансии из твоего поиска, пишет под каждую
сопроводительное письмо по фактам из резюме (через Requesty, модель Gemma),
откликается в твоём браузере и прикладывает письмо. Работает полностью
автоматически, без ручной вычитки.

## Что получишь на выходе

После запуска `auto` (или связки collect, draft, send):

1. На hh появляются **отклики** от твоего имени, в большинстве случаев с
   приложенным сопроводительным письмом.
2. В `state.sqlite` (таблица `vacancies`) остаётся **журнал**: вакансия, компания,
   текст письма, предупреждения проверки, статус и время.
3. В терминале строки вида `sent: <вакансия> | <компания> <ссылка>` по каждому
   отклику и итоговая сводка сбора (`added N new, skipped M known, K failed`).

### Статусы вакансии

| Статус | Значение |
|---|---|
| `new` | собрана, письмо ещё не написано |
| `drafted` | письмо написано, отклик ещё не отправлен |
| `sent` | отклик отправлен (смотри в терминале, ушло ли письмо; см. ниже) |
| `skipped` | пропущена (откликался раньше) |
| `manual` | автоматически откликнуться не получилось (анкета, тест, всплывающее окно): откликнись сам |

Две оговорки по `sent`:
- Если в терминале есть `!! response sent WITHOUT the letter`, отклик ушёл, а
  письмо нет (hh не дал приложить его). Письмо лежит в базе, при желании отправь
  его в чате отклика вручную.
- Письма с телефоном или e-mail внутри бот не отправляет (`hold (contacts in
  letter)`), они остаются `drafted`.

## Первая настройка (один раз)

    python3 -m pip install -r requirements.txt
    python3 -m playwright install chromium
    cp .env.example .env      # вписать REQUESTY_API_KEY=... без кавычек
    python3 bot.py login      # откроется окно, войди в hh сам, затем Enter в терминале

Проверь `resume_facts.md`: письма строятся только по нему. Контактов в нём быть не
должно, любой факт в нём бот может написать работодателю.

## Плейбук: как запускать
### Основной способ: одна команда

    python3 bot.py auto "https://hh.ru/search/vacancy?area=2&area=1&from=header-menu&hhtmFromLabel=drawer_filter&hhtmFrom=vacancy_search_list&text=DevOps&experience=between3And6&experience=between1And3&search_field=name&search_field=company_name&search_field=description&work_format=REMOTE&work_format=HYBRID&work_format=ON_SITE&enable_snippets=true&hhtmSource=vacancy_search_list&hhtmSourceLabel=vacancy_search_list&L_save_area=true" --pages 4 --max 50

Что произойдёт по шагам:
1. **Сбор.** Бот просматривает до `--pages` страниц выдачи (по 50 вакансий) и
   сохраняет до `--max` новых вакансий (паузы 10-30 с между страницами).
2. **Письма.** Для каждой новой вакансии генерируется письмо, строго по одному
   запросу за раз (потоков нет): у бесплатной модели жёсткий лимит запросов.
   Интервал между запросами подстраивается сам: при 429 растёт вдвое, при успехах
   медленно сокращается. Если квота исчерпана, бот останавливает генерацию (письма
   остаются в `new`) и переходит к отправке уже готовых.
3. **Отклики.** По очереди: открыть вакансию, нажать «Откликнуться», приложить
   письмо. Лимит 100 откликов в день.

URL поиска бери из адресной строки hh после настройки фильтров, без `page=`.
Окно браузера открывается само и не должно быть закрыто до конца. Партия на
100 вакансий занимает от получаса до нескольких часов (в основном паузы).

### По шагам (если нужно контролировать этапы)

    python3 bot.py collect "<URL>" --pages 2 --max 20   # только собрать
    python3 bot.py draft --limit 20                     # только написать письма
    python3 bot.py send                                 # только откликнуться
    python3 bot.py review                               # интерактивно, по одной (вручную)

### Как посмотреть результат

    sqlite3 state.sqlite "select status, count(*) from vacancies group by status"
    sqlite3 state.sqlite "select updated, company, title, url from vacancies where status='sent' order by updated desc limit 20"
    sqlite3 state.sqlite "select company, title, url from vacancies where status='manual'"
    sqlite3 state.sqlite "select letter from vacancies where id='<id вакансии>'"

## Панель управления (Docker, работает всегда)

Страница `http://localhost:8765` (доступна только с твоего компьютера):
- статистика только по откликам программы (сегодня, 7 дней, всего, очередь, ручные, график за 14 дней, какое письмо ушло: своё, от hh или без письма, последние отклики);
- запуск «отправить N откликов» с прогресс-баром (и опцией «сначала собрать новые вакансии»);
- кнопка «Остановить» (бот доделывает текущую вакансию и закрывается сам), при зависании «прервать принудительно».

Запуск и обслуживание:

    python3 bot.py export-session        # один раз (и при смене пароля): сохранить сессию hh для контейнера
    docker compose up -d --build         # собрать и запустить; restart: unless-stopped держит его всегда
    docker compose logs -f               # журнал контейнера
    docker compose down                  # остановить

В контейнере бот работает в обычном (не headless) Chromium на виртуальном экране, сессия hh берётся из
`data/session.json`, база и состояние запусков лежат в `data/` (общие с запуском с компьютера).
Чтобы контейнер стартовал после перезагрузки Mac, включи в Docker Desktop «Start Docker Desktop when you sign in».

Важно: не запускай одновременно отправку из панели и `python3 bot.py ...` на компьютере: оба идут на hh
с одного аккаунта и пишут в одну базу.
Если hh покажет капчу, запуск остановится со статусом «Капча»: реши её в браузере на компьютере
(`python3 bot.py login`) и снова выполни `python3 bot.py export-session`.

## Предохранители

- Лимит 100 откликов и 100 писем в день (`DAILY_LIMIT` в `bot.py`).
- Паузы 10-30 с, таймауты ожидания 3 с (уменьшено по решению пользователя, это
  ускоряет работу, но чаще приводит к отклику без письма).
- Повторно на вакансию, где уже есть отклик, бот не откликается.
- При капче бот останавливается и ждёт в терминале; капчу он не решает.
- После 3 подряд вакансий, требующих ручного отклика, бот останавливается
  (признак того, что hh поменял вёрстку).

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `rate limited` / `Free-model quota exhausted` | бесплатная модель Requesty исчерпала лимит запросов. Бот ждёт и замедляется сам; если остановился, подожди (возможно, до следующих суток) и запусти `draft` снова, либо смени `MODEL` в `letter.py` на платную |
| `... profile is already in use` | от прошлого запуска остался Chromium: `pkill -f "hh-bot/.profile"` |
| Сбор падает: `selector ... not found` | hh поменял вёрстку: `python3 bot.py check-selectors <url>` (запусти на странице поиска и на странице вакансии), поправь `SEL` в `bot.py` |
| Много `manual` | у этих вакансий анкета или тест, откликайся вручную |
| Отклики идут без письма | слишком короткий таймаут (3 с): подними `timeout=3_000` в `respond()` в `bot.py` до 8_000 |
| Процесс завис (`^Z`, suspended) | вернуть: `fg`; завершить: `kill %1`. Не закрывай вкладку с запущенным ботом принудительно |

## Риски

- Массовые автоотклики противоречат правилам hh: возможны капча и блокировка
  аккаунта. Бот не маскируется под человека и не обходит защиту, но риск остаётся.
- Письма уходят без вычитки. Модель может приукрасить опыт (например, написать
  «Senior» там, где вакансия просто «DevOps-инженер»). Текст каждого письма лежит
  в базе.
- `.profile/` содержит живую сессию hh (куки): держи папку вне облачной синхронизации,
  в git она игнорируется. `.env` с ключом тоже игнорируется.
