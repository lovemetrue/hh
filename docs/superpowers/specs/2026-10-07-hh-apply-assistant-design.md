# hh.ru apply assistant: дизайн

Дата: 2026-10-07. Статус: утверждён пользователем в чате, ждёт ревью файла.

## Цель

Полуавтомат для откликов на hh.ru: бот собирает вакансии, пишет под каждую
сопроводительное письмо по фактам из резюме и подставляет его в форму отклика
в реальном браузере пользователя. Кнопку отправки нажимает человек.

## Почему браузер, а не API

- Публичный OpenAPI hh (`api.hh.ru/openapi/specification/public`) не содержит
  метода создания отклика для соискателя (проверено 2026-10-07). Есть только
  `POST /token`, чтение списка откликов и `/me`.
- Веб-отклик идёт через внутренний `POST /applicant/vacancy_response/popup`
  (multipart: `resume_hash`, `vacancy_id`, `letterRequired`, `captchaText`, ...) по
  сессионным кукам и XSRF-токену, с отпечатком браузера и возможной капчей
  (по `hh.ru.har`). Воспроизводить его скриптом вне браузера не будем.

## Границы (что бот НЕ делает)

- Не нажимает финальную кнопку отправки отклика.
- Не обходит капчу и антибот, не воспроизводит внутренние запросы вне браузера.
- Не вводит пароль: вход в hh делает пользователь в окне браузера.
- Не отправляет контакты резюме в LLM.

## Стек

Python 3, Playwright (headed, persistent profile в `hh-bot/.profile/`), sqlite3 из
stdlib, `requests` или `urllib` для Requesty (OpenAI-совместимый API,
`https://router.requesty.ai/v1/chat/completions`, модель `google/gemma-4-31b-it`).
Ключ: `REQUESTY_API_KEY` в `.env` (в `.gitignore`).
Комментарии и вывод скриптов по-английски.

## Команды

1. `collect <search-url>`: открывает сохранённый поиск hh, собирает ссылки и
   тексты вакансий, пропускает уже виденные и те, где уже есть отклик. Результат в
   `state.sqlite` (`vacancies`: id, url, title, company, description, status).
2. `draft`: для вакансий со статусом `new` генерирует письмо только по
   `resume_facts.md`. Русский по умолчанию, английский для английских вакансий.
   Статус `drafted`. Дневной лимит черновиков.
3. `review`: по одной вакансии показывает заголовок, требования и черновик.
   Действия: send / edit / skip. На send бот открывает вакансию, копирует письмо
   в буфер обмена и ждёт. «Откликнуться» нажимает сам пользователь (клик по этой
   кнопке на hh может отправить отклик сразу, без письма); если поле письма
   появилось, бот заполняет его. Отправку тоже жмёт пользователь. Статус
   `sent` / `skipped` по маркеру на странице или по подтверждению пользователя.

   Файлы: помимо `bot.py` код разнесён на `store.py` (очередь в sqlite) и
   `letter.py` (промпт, вызов Requesty, проверки), тесты в `test_store.py` и
   `test_letter.py`.

## Защита

- Дневной лимит откликов (по умолчанию 15) и черновиков, случайные паузы 20–60 с.
- Капча, неожиданное окно, смена вёрстки (не найден `data-qa` селектор):
  остановка и передача управления человеку.
- Селекторы только по `data-qa`; уточняются по HAR и живой странице до основного кода.

## Промпт письма

Вход: `resume_facts.md` + текст вакансии. Правила: только факты из резюме, ничего
не придумывать (технологии, сроки, должности), 700-1000 знаков, без штампов и
эмодзи, без контактов, обращение без имени, если оно не указано в вакансии.

## Тест

Один smoke-тест: сгенерированное письмо не содержит телефона, e-mail и названий
технологий, которых нет в `resume_facts.md`.

## Риски

- Правила hh могут запрещать автоматизацию: поэтому человек в цикле, лимиты, без обхода капчи.
- Вёрстка hh меняется: селекторы чинятся вручную, бот падает громко, а не молча.
- Gemma-31B склонна приукрашивать: ограничение промптом плюс smoke-тест.
